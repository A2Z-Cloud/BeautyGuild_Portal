**Date:** 24 October 2026

## Scope completed in this iteration

### Milestone 1: CRM Workspace and Record Experience

| Item | Code/behaviour | Verification |
| --- | --- | --- |
| CRM field metadata | `v12-crm.js` calls `ZOHO.CRM.META.getFields` and uses CRM field labels, visibility and view flags. | Mock metadata test; **real CRM permissions not yet tested** |
| CRM layouts | Uses `ZOHO.CRM.META.getLayouts` to group available fields into the selected CRM layout sections; All CRM Fields toggle. | Mock layout test; **real CRM layout response must be verified** |
| CRM related lists | Uses `ZOHO.CRM.META.getRelatedList` where available, with explicitly labelled fallbacks for known relations. Right-side related-list navigator replaces stacked cards on selected CRM records. | Mock detail verification; **CRM related-list API names must be verified live** |
| Related records | Lazy `getRelatedRecords` per selected list, paging, field tables and navigation into supported CRM records; user-facing error distinction. | Source verification; live CRM permission and pagination tests pending |
| Record pages | Header, statuses, actions, Details, Timeline, Processing and related-list views; existing native CRM Notes/Tasks and processing checklists preserved. | Mock render test; live CRM test pending |
| Lists | CRM-style multi-column tables for Customers, Membership, Insurance and Accreditation; existing API pages and explicit loaded-record filter plus new CRM-wide word search, with further search-result pages. | Code/syntax verified; **search results and per-module field coverage need live testing** |
| Sensitive fields | CRM invisible metadata fields are not shown in metadata-driven detail pages. | Mock test |
| Static hosting | Existing Slate Static HTML root and assets preserved. New JS/CSS modules loaded from `index.html` and `widget.html`. | Source/assets verified; **not independently verified inside live Slate iframe** |

**Design limitation:** This is a first implementation of metadata-driven rendering, not a claim that Zoho CRM's complete native record editor, every Blueprint button, subform or complete audit timeline has been replicated. Native CRM handles unsupported actions.

**Update discipline:** `portal-defs/*` is a source snapshot, not a magically live import from the Portal build. When Portal V2 changes its question logic, update the same files from `apps/portal/src/` and run regression checks. Avoid maintaining a third independently rewritten insurance ruleset.

## Testing and release gates

1. Confirm the Slate page loads `v12-crm.js`, `v12-journeys.mjs`, every `portal-defs` module and `v12.css` with no 404/CORS/MIME error; verify within a CRM Web Tab.
2. Check CRM SDK initialization and actual user permissions; test restricted and admin CRM profiles. Confirm sensitive fields hidden even if record value is returned.
3. Test real CRM metadata and layout sections for Contact, Membership Deal, Insurance Policy and Accreditation.
4. Open an Insurance Policy, switch between Details, Timeline, Processing and every supported related-list navigator item; verify child drill-in, pagination and explicit API errors.
5. Browse each module with meaningful columns, load more CRM records, filter loaded records and use **Search all CRM** for records beyond loaded pages.
6. Select an existing customer and start Membership, Insurance and Accreditation. Validate contact prefill and every conditional question. Confirm no hidden questions are inadvertently required.
7. Test Insurance: non-salon, salon, named employees, treatments, teaching, property, STOP and REFER, declarations and demands/needs.
8. Test Accreditation: UK/international, additional tutors, Courses availability/completeness, qualifications, start dates, declarations and missing inputs.
9. Confirm no Stripe payment is initiated; no financial or policy status updated and no CRM application is created via the in-memory questionnaire.
10. Recheck `tests/v12.test.cjs` and the original V1.1 tests in CI or a local Node.js environment, then visually verify the Slate deployment.

**Known unresolved integration requirements (next milestone):**

- Secure CRM staff identity/authorisation to the existing Catalyst `beauty_guild_api` backend.
- Real CRM-backed shared staff/customer draft persistence, optimistic revisions, verified Contact ownership and staff attribution.
- Authoritative Catalyst Insurance quotation, membership pricing, sanctions, underwriting, flood/subsidence results and detailed CRM screening audit.
- Final payment enablement and new Creator V2 payment processing, deliberately excluded from this build.

## Release assessment

**Development candidate ready for Slate/CRM sandbox visual and integration QA; not production/UAT signed off.** Milestone 1's core UI implementation is present. Milestone 2's questionnaires and prefill are present, but **cross-channel Save/Resume and server-side submission are blocked pending the authorised Catalyst staff adapter**. Do not represent the overall milestone as fully complete without those dependencies.
